# uTools 源笔记插件 SourceNote

## Goal

多领域学习者记录"源笔记"（source note / 文献笔记）的 uTools 插件：以**学习对象**为载体（一本书 / 一篇论文 / 一门课程 / 一个 GitHub 项目…），用最低成本记录要点、用最快速度检索。源笔记是写主卡（独立 Zettelkasten APP）之前的**跳板**：记录即沉淀，搜到即用。

## Background（背景与确认事实）

- 卡片盒笔记法背景：卢曼写书卡前先对文献做阅读笔记，记录要点，之后挑选有价值内容进入主卡系统。本插件只做"阅读笔记"环节，主卡系统是用户另行规划的独立 APP，不在本插件范围。
- 学习来源多样：书、论文、课程、视频、GitHub、文章、播客等，需要自定义扩展，不能只支持书本/论文。
- 全部笔记**扁平管理**（无文件夹、无层级），对象与笔记的归属通过字段关联，不通过目录结构。
- uTools 插件窗口默认 800×600，UI 必须紧凑，内容区不设常驻搜索框。

## Requirements

### 数据模型

- **R1 对象（对象笔记）**：携带 `source_type` + 来源元数据（作者/URL/年份等），是钉住与归档的**生命周期单元**。新建笔记时必须归属一个对象。
- **R2 普通笔记**：通过 `object_id` 挂到对象下；正文为纯 Markdown；可挂多个标签。
- **R3 标签**：独立实体 `{name, aliases[]}`；笔记与标签多对多；数据层结构化（重命名/合并 O(1)），但 UI 不做标签管理页。
- **R4 来源类型**：内置 book / article / video / paper / github / course 六种 + 用户自定义（在设置页增删改枚举）；该枚举同时驱动"新建对象的来源下拉"与"内容区来源筛选器"。

### 视图与导航

- **R5** 侧边栏顶部分段控件：`首页 | 标签 | 归档 | 设置`，点击**整页切换**，每视图只显示自己的内容。
- **R6** 两级导航恒定：左侧列表（对象/标签）→ 内容区笔记卡片列表 → 点击卡片 → 笔记全文。全产品只有"卡片列表"与"笔记全文"两种内容形态。
- **R7 首页视图**：侧边栏 = 钉住对象列表 + 钉住标签列表（标签兼作主题分类）。点击对象 → 该对象笔记卡片列表；点击标签 → 该标签跨对象的笔记卡片列表。
- **R8 标签视图**：侧边栏 = 全部标签（带笔记计数），点击 → 该标签笔记卡片列表。
- **R9 归档视图**：侧边栏 = 已归档对象列表，点击 → 只读查看（对象详情 + 笔记全文）。
- **R10 设置视图**：来源类型枚举管理（增删改）+ 偏好设置（默认排序等）。
- **R11 对象详情页**：顶部 = 来源元数据条（类型/作者/URL/标签）+ [新建笔记][排序]，下方 = 该对象全部笔记卡片列表。**列表恒为列表形态**，笔记数为 1 与为 N 时渲染一致，不做特判。
- **R12 生命周期**：钉住与归档都是**对象级**且互斥——归档对象时确认框提示"将归档该对象及其 N 条笔记，转为只读"，确认后自动取消钉住；普通笔记没有钉住/归档操作，只有删除。
- **R13** 归档是状态不是隔离区：归档对象的笔记仍可被全文搜索与标签命中查看（只读）。

### 标签

- **R14** 新建/编辑笔记输入标签时，下拉联想补全，模糊匹配 `name` 与所有 `aliases`。
- **R15** 标签别名：如 `深度学习` = `deep learning` = `DL`；写入时经别名归并到同一标签；展示统一显示规范名，别名可编辑（标签详情/右键编辑）。

### 搜索

- **R16** 使用 uTools 子输入框（`setSubInput`）承担全文搜索：激活插件后 uTools 搜索栏输入即搜，范围 = 标题 + 标签 + 正文全文。支持语法：`type:book`（来源类型）、`#标签`、普通关键词，可组合。
- **R17** 内容区标题行右侧：排序菜单（最近更新 / 创建时间 / 标题 / 相关度）+ 来源类型筛选下拉；不常驻搜索框。

### 写作

- **R18** 新建笔记：必选归属对象（联想已有对象，可即时新建对象），填写标题 + Markdown 正文 + 标签。新建对象：选来源类型、填来源元数据。

## Acceptance Criteria

- [ ] **AC1** 新建对象（选来源类型、填元数据）→ 在该对象下新建多条笔记 → 对象详情页按时间倒序展示全部笔记卡片
- [ ] **AC2** 钉住对象 → 出现在首页"钉住对象"区；归档对象弹出确认（提示 N 条笔记转只读）→ 移入归档视图且自动取消钉住；归档内不可编辑
- [ ] **AC3** 同一对象有 1 条与有 20 条笔记时，详情页均为相同卡片列表形态
- [ ] **AC4** 新建笔记输入 "deep" 时下拉命中别名含 "deep learning" 的 `#深度学习` 标签；选择后写入的是规范名
- [ ] **AC5** 标签视图列出全部标签及计数；点击后内容区展示该标签跨对象的笔记卡片列表
- [ ] **AC6** 子输入框输入 `type:book 注意力` 时，仅返回来源为 book 且标题/正文/标签命中"注意力"的笔记
- [ ] **AC7** 设置页新增来源类型"播客"后，新建对象的来源下拉与内容区来源筛选器立即出现"播客"
- [ ] **AC8** 800×600 窗口下四个视图切换正常、无横向滚动、内容区信息密度合理
- [ ] **AC9** 归档对象的笔记仍能被全文搜索命中，点击可只读查看全文
- [ ] **AC10** 新建笔记必须归属对象；未选对象时无法保存（编辑态强提示）

## Out of Scope

- 主卡 Zettelkasten APP（独立产品，另行规划）
- 笔记间双向链接 / 引用网络 / 知识图谱（源笔记是跳板，不构建知识网络）
- 多设备同步、云端备份
- 复杂采集能力（PDF 标注、网页剪藏、文件导入）
- 模板系统、每日笔记、时间轴/统计看板
- 标签管理页（层级、颜色、分类）；标签只有"钉住/取消钉住 + 别名编辑 + 删除"

## MVP Scope（已确认：方案 B 核心闭环先行）

**第一版交付**：首页视图 + 标签视图 + 对象/笔记 CRUD + 标签（别名+联想补全）+ 全文搜索（type: 语法）

**第二版交付**（数据层 schema 一次设计到位，不返工）：归档视图、设置视图（来源枚举管理）

第一版验收覆盖 AC1-AC6、AC8、AC10；AC7、AC9 随第二版验收。
