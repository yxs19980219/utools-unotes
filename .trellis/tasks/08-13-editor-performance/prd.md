# 编辑体验全面升级（对齐 Typora 流畅度与所见即所得）— 原：编辑器卡顿诊断与性能优化

## Goal

用户反馈当前 markdown 编辑体验差。已调研 Typora 底层：Electron + CodeMirror 5 深度定制 + 自研 GFM 引擎，即时渲染只改显示不改内容。本项目同为 CodeMirror 6 + 自研装饰（markdownDecorations.ts）。本轮需求 16 项：工具栏样式、头部布局与元信息、工具栏所见即所得、内容区渲染细节、流畅度。

## Requirements

### 一、工具栏样式
1. 编辑区快捷操作按钮栏：上下用两条细线包住（不再裸在外面）

### 二、笔记头部布局与元信息
2. 标题字号加大（当前偏小）
3. 标签改为小字号、紧跟标题后排列；一行放不下时才折到第二行
4. 没有标签时标题独占一行，不留空行
5. 删除「更新于」文字
6. 编辑功能栏最右侧放一个圆形感叹号按钮（ⓘ）
7. ⓘ 点击弹出元信息面板：创建时间、更新时间、字数、可点击跳转的大纲列表

### 三、工具栏按钮所见即所得（按下后直接看到效果，不再显示裸语法）
8. 通用原则：按钮按下后直接呈现格式效果，而不是插入裸语法文本
9. 图片：点击后打开电脑文件选择弹窗，插入后直接显示图片
10. 代码块：插入一个可输入代码的代码框，且可选择常见语言
11. 表格：插入一个真实表格（可编辑、可增删行列）

### 四、内容区渲染细节
12. 标题：输入 # 号时，# 的大小跟随标题级别（1 个 # 很大、2 个 # 略小，以此类推）
13. 无序/有序列表与行首有间距（不顶着行首）；Tab 嵌套后距离更大（层级清晰，当前距离很小）
14. 列表嵌套层级的符号依次变化：实心圆点 → 空心圆点 → 实心方点
15. 软换行：输入超过可见区域时按视口宽度自动换行（现在行尾一直往后延伸）
16. 流畅度：输入不流畅，与 Typora 体验差距明显；调研优秀 markdown 笔记的交互设计

## 任务地图（parent → child）

```
08-13-editor-performance（parent）
├── 08-13-perf-smoothness   ① 流畅度优化（需求16）→ 最先执行
├── 08-13-wysiwyg-toolbar   ② 所见即所得工具栏（需求8-11）→ 最后执行，依赖①的性能基线
├── 08-13-header-metainfo   ③ 头部布局+元信息面板（需求2-7）
└── 08-13-render-details    ④ 渲染细节+工具栏样式（需求1、12-15）
```

执行顺序：① → ④ → ③ → ②（先修卡顿地基，轻量项快速见效，最重的所见即所得最后攻坚）。

依赖关系（写入各 child artifact）：
- ② 依赖 ①：所见即所得要加 Widget/复杂装饰，需在性能基线之上进行，避免在卡顿编辑器上加更重的渲染
- ④ 与 ③ 无强依赖，均可独立于 ① 执行（但 ① 的装饰性能重构可能与 ④ 的装饰修改重叠，④ 需在 ① 合并后 rebase）

## Acceptance Criteria（跨 child 集成验收，最终在 parent 层验证）

- [x] 全部 16 项需求逐项通过对应 child 验收：
  - ① perf-smoothness：需求 16 流畅度（17.8 倍提升）
  - ④ render-details：需求 1、12-15（工具栏细线/标题#字号/列表缩进与嵌套符号/软换行）
  - ③ header-metainfo：需求 2-7（标题字号/标签排版/删更新于/ⓘ 元信息面板）
  - ② wysiwyg-toolbar：需求 8-11（图片/代码块语言/表格增删行列/插入即渲染）
- [ ] 最终集成：编辑长笔记（≥500 行）输入/滚动流畅——uTools 实测待用户确认（headless 已验证 9.2ms/键、DOM 变更 3 处）
- [x] 无回归：保存、切换笔记、快捷插入、只读视图渲染正常（ui-smoke 47 项全绿，各 child 回归全过）
