# SourceNote 二期：归档与设置视图 + 编辑器增强

## Goal

一期（v1.0.0）已交付核心闭环（首页/标签视图、对象模型、快速创建、即时渲染编辑器、全文搜索）。二期补齐：**归档视图**（对象级归档 + 只读语义，验收 AC2 归档部分 / AC9）、**设置视图**（来源类型枚举管理，验收 AC7）、**编辑器增强**（表格等高级语法、草稿保护），并解决一期遗留确认项。

## Background（现状与一期约定）

- 一期已实现：四视图分段控件（归档/设置 tab 置灰 + Tooltip「二期开放」）、store 层 `setArchived`（归档自动取消钉住，R12）与搜索命中归档（AC9 语义）已就绪、`db.ts` 的 `getSourceTypes/saveSourceTypes` 枚举读写已就绪、NoteView 只读渲染（归档隐藏编辑 + 「已归档」角标）已就绪
- 一期遗留：`useSourceTypes` 模块级缓存无失效机制；NoteForm/NoteView 编辑中切走直接丢弃草稿；表格等复杂语法编辑器内保持纯文本
- 一期遗留确认项（用户尚未拍板，本期实现前确认）：① 链接色可见性（浅色模式 `--primary` 是浅灰 #E7E7E7，编辑器/只读渲染中的链接几乎不可见）② 归档笔记卡片是否保留删除入口（当前按"归档=只读"隐藏了编辑与删除）
- 工作方式约定（spec Workflow Conventions）：交互流程必须写清到"按钮级"；渲染层改动必须跑 `npm run ui-smoke`

## Requirements

### 归档视图

- **R1** 侧边栏顶部分段控件放开「归档」tab：侧边栏 = 已归档对象列表（标题 + 来源图标 + 归档时间），点击 → 内容区只读对象详情（元数据条 + 笔记卡片列表，与首页对象详情同构，仅只读）
- **R2** 归档入口：对象详情元数据条「归档」按钮（home 首页对象详情可操作）→ AlertDialog 确认：「将归档《对象名》？其下 N 条笔记将一并转为只读」→ 确认后 `setArchived(true)`（自动取消钉住），对象移入归档视图
- **R3** 取消归档：归档视图内对象详情元数据条「恢复」按钮 → 确认后 `setArchived(false)` 恢复活跃，重新出现在首页钉住区之外（需重新钉住才能上首页）
- **R4** 只读语义：归档对象的对象详情/笔记正文/卡片流全部不可编辑（编辑器不出现、写正文/编辑按钮隐藏、卡片悬停无编辑入口）；「已归档」Badge 展示；归档笔记仍可被全文搜索与标签命中（AC9，一期已实现）
- **R5** 归档对象详情内笔记卡片点击 → 只读 NoteView（一期已实现，验收即可）

### 设置视图

- **R6** 分段控件放开「设置」tab：设置页包含「来源类型」管理区块 + 「偏好」区块
- **R7** 来源类型管理：列表展示全部类型（内置 book/article/video/paper/github/course 带「内置」标记 + 自定义类型），支持：新增（输入名称，去重校验，拒绝与既有类型同名/同音近似？——仅精确去重即可）、重命名（内置类型允许改显示名？——**决策：内置类型名称锁定不可改不可删**，仅可自定义增删改）、删除（AlertDialog 确认；已被对象引用的类型删除时提示「有 N 个对象使用该类型」并允许强制删除——**决策：允许强制删除，被引用对象保留原类型字符串，筛选器不再出现该类型**）
- **R8** 枚举驱动单一数据源：设置页的增删改即时生效于「新建对象来源下拉」与「内容区来源筛选器」（修复 `useSourceTypes` 缓存失效问题：改为 store 或带刷新回调）
- **R9** 偏好设置（MVP 范围）：默认排序（最近更新/创建时间/标题），持久化到 `setting/prefs`，内容区列表初始排序读取该值

### 编辑器增强

- **R10** 表格即时渲染：装饰器支持 GFM 表格（`| 列 | 列 |` + 分隔行），渲染为表格样式（边框/表头加粗/等宽对齐保持文本流）；光标行内表格保持可编辑文本
- **R11** 草稿保护：NoteView 正文编辑中切走（返回/切换对象/切换视图/关闭插件）时，若有未保存改动 → 确认提示（「放弃更改 / 取消」），不弹窗打断则自动暂存（localStorage `draft:<noteId>`），下次进入恢复并提示
- **R12** 编辑态切走同样保护：NoteForm（标题/标签编辑）未保存改动切走时确认提示（一期直接丢弃）

### 遗留项

- **R13** 链接色修正（用户确认后）：编辑器与 MarkdownView 中链接使用 `foreground + underline`（或用户指定方案），保证浅色模式可见
- **R14** 归档卡片删除入口（用户确认后）：若用户选择保留删除，归档笔记卡片悬停恢复「删除」入口（仍隐藏编辑）

## Acceptance Criteria

- [ ] **AC1** 归档对象：首页对象详情点「归档」→ 确认框提示 N 条笔记转只读 → 确认后从首页钉住区消失、归档 tab 侧边栏出现、自动取消钉住
- [ ] **AC2** 归档视图点对象 → 只读对象详情（无新建/编辑/归档按钮，有「恢复」）→ 点笔记 → 只读 NoteView（无编辑器入口）
- [ ] **AC3** 归档视图「恢复」对象 → 对象回到活跃态（首页不自动钉住），其笔记可正常编辑
- [ ] **AC4** 设置页新增来源类型「播客」→ 返回后新建对象来源下拉与内容区筛选器立即出现「播客」（无需刷新）
- [ ] **AC5** 设置页删除被引用类型 → 确认提示含引用计数；删除后筛选器/下拉不再出现；已引用对象的来源类型字段不受影响
- [ ] **AC6** 设置页偏好选「创建时间」→ 对象详情笔记列表初始按创建时间排序（重启后仍生效）
- [ ] **AC7** 编辑器输入 GFM 表格 2×2 → 渲染为表格样式；光标进入表格单元格仍可正常编辑文本
- [ ] **AC8** 笔记正文编辑中（有改动）点返回 → 弹确认；选「取消」留在编辑态；选「放弃」丢失改动并返回
- [ ] **AC9** 编辑中强制离开（如切视图）→ 草稿自动暂存；重新进入该笔记 → 草稿恢复 + 提示「已恢复未保存的草稿」
- [ ] **AC10** 归档笔记卡片行为符合 R14 用户拍板结果（保留删除 or 纯只读）
- [ ] **AC11** 链接在浅色/深色模式下均清晰可见（R13 拍板方案）
- [ ] **AC12** 800×600 下归档/设置视图无横向滚动；`npm run ui-smoke` 全绿（新增归档/设置流程断言）

## Out of Scope（本期不做）

- 归档笔记单独删除/恢复（归档是对象级生命周期；笔记无独立归档态——R14 仅确认删除入口保留与否）
- 标签管理页、模板系统、双向链接（一期 Out of Scope 不变）
- 来源类型的图标自定义、拖拽排序
- 草稿的跨设备同步（localStorage 本地即可）
