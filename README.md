# utools-unotes（源笔记）

> 不是又一个笔记软件，而是主卡（Zettelkasten）写作前的**阅读笔记阶段**：记录"我在学什么、来自哪里"，学完归档，搜到即用——实践与提炼是之后的事，在主卡里完成。

## 为什么是"源笔记"

卢曼写书卡之前，会先对文献做**阅读笔记**：记录他认为有价值的要点，日后沉淀、挑选，有价值的才提炼进主卡系统。这套前置笔记就是"源笔记"——它是主卡的原料库，不是成品。

今天的我们和卢曼的不同在于**来源**：不只是书和论文，还有课程、视频、GitHub 项目、文章、播客……来源多样，但"先记录、后提炼"的路径不变。

市面上的笔记软件用**科目/主题分类**（文件夹体系）组织知识——那是主卡阶段的组织方式。源笔记阶段不该背这个包袱：它只需要回答三个问题。

## 核心理念：只关心三件事

| 问题 | 答案 | 插件里的落点 |
|------|------|-------------|
| **学的是什么类型？** | 书 / 课程 / 视频 / 论文 / GitHub / 播客… | 来源类型（内置 6 种 + 自定义） |
| **来自哪里？** | 哪本书、哪个项目、哪门课 | 学习对象（笔记的唯一归属） |
| **学完了吗？** | 进行中 / 已归档 | 生命周期（归档 = 终点状态） |

**全库只有一个组织维度：对象。** 没有文件夹、没有科目层级、没有主题树——对象即载体，笔记挂对象，对象管生命周期。

### 我们刻意不做的事

- **不做科目/主题分类**——主题只是标签，标签只是检索入口；钉住一个标签就是"这段时间关注它"，不维护任何分类体系
- **不管理标签**——标签多就多、旧就旧，不钉住自然退场，它唯一的作用是帮你搜到
- **不做知识网络**——双向链接、主题聚类、知识图谱是主卡阶段的活，源笔记止步于"记录 + 搜到"

## 工作流：记录 → 检索 → 提炼

```
记录 ──→ 检索 ──→ 提炼（主卡，本插件之外）
 │         │
 │         └─ 全文搜索：type:book 注意力 #深度学习
 │            搜到即用，这是源笔记的全部价值
 └─ 低摩擦：标题 + 标签即卡片 → 点开即写 → 自动保存
    写完就归档：学完的对象归档为只读，随时可恢复
```

源笔记是**跳板**不是终点：它的产出不是完美的知识体系，而是"我当时认为值得记住的要点 + 我能再次找到它们"。实践沉淀、提炼主卡——在另一个 APP 里，从检索结果开始。

## 功能总览（理念的落点）

- **对象模型**：来源类型（可自定义）+ 来源元数据 + 钉住 / 归档 / 恢复，全库扁平
- **三视图 + 设置**：首页（进行中的对象 + 钉住标签）/ 标签 / 归档 / 设置（来源类型管理、默认排序）
- **快速创建**：新笔记只填标题（留空自动「未命名」）+ 标签，一步成卡片
- **即时渲染编辑器**：`#` / `-` / `**` / 表格输入即渲染，光标行淡色标记；源码始终是标准 Markdown
- **实时保存**：正文停止输入 500ms 自动落盘，没有保存按钮
- **全文搜索**：uTools 子输入框即搜，`type:` / `#标签` / 裸词 AND 组合，相关度排序
- **标签别名归并**：`deep learning` = `深度学习` = `DL`，输入即联想，展示永远一致
- **深色模式**：跟随系统；800×600 紧凑布局

## 快速上手

```
1. 新建对象：侧边栏「＋」或首页空态引导（书 / 课程 / GitHub 项目…，填来源信息）
2. 记笔记：对象详情「＋新笔记」→ 标题（可留空）+ 标签 → 保存
3. 写正文：点击卡片直接写（即时渲染 + 自动保存）
4. 检索：uTools 搜索栏输入 type:book 注意力 或 #深度学习
5. 归档：学完了 → 对象右键「归档」（只读，可恢复）；首页只留进行中的
6. 提炼：从搜索/归档中找到要点，去主卡 APP 写你的卡
```

## 安装

从 [GitHub Releases](https://github.com/yxs19980219/utools-unotes/releases) 下载最新 zip：uTools → 插件 → 开发者工具 → 导入。

## 开发

```bash
npm install        # 安装依赖
npm run dev        # 开发模式（uTools 开发者工具接入 public/，HMR）
npm run build      # 构建 dist/（发布产物，无 development 字段）
npm run typecheck  # TypeScript 检查
npm run smoke      # 数据层冒烟（19 断言）
npm run smoke:stores      # 状态层冒烟（18 断言）
npm run smoke:decorations # 编辑器装饰冒烟（8 断言）
npm run ui-smoke  # 渲染层冒烟（47 断言，需 dev server + 系统 Edge/Chrome）
```

> 上架：`npm run build` 后上传 `dist/` 目录或打包 zip，无需 upx。
> 测试体系：无单测框架，以 4 个冒烟脚本替代（node 直测 + 无头浏览器真实 DOM 验证）。
